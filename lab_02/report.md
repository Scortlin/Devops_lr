## 4. Описание компонентов

### 4.1 Генератор данных (`generate_data.py`)

Скрипт запускается **один раз на хосте** перед `docker compose up`. Он создаёт файл `data/marketing_spend.csv` с 2 000 строк с затратами и выручкой каналов за 2023 и 2024 год.

Поля датасета:

| Поле | Тип | Описание |
|------|-----|----------|
| campaign_id | INT | Уникальный идентификатор маркетинговой кампании |
| date | DATE | Дата проведения кампании |
| channel | VARCHAR | Канал маркетинга |
| region | VARCHAR | Регион |
| product | VARCHAR | Продвигаемый продукт |
| impressions | INT | Количество показов рекламы |
| clicks | INT | Количество кликов по рекламе |
| spend | INT | Затраты на кампанию |
| revenue | INT | Выручка от кампании |


### 4.2 Dockerfile (`app/Dockerfile`)

Соблюдены все требуемые «хорошие практики»:

| Практика | Реализация |
|----------|-----------|
| Конкретная версия образа | `python:3.11-slim` (не `latest`) |
| Непривилегированный пользователь | `useradd -u 1000 appuser`, далее `USER appuser` |
| Кэш слоёв | `COPY requirements.txt` + `pip install` до `COPY *.py` |
| Очистка кэша | `rm -rf /var/lib/apt/lists/*` и `pip --no-cache-dir` |
| `.dockerignore` | Исключены `__pycache__`, `.git`, `venv`, `.env` |

Один и тот же образ используется для двух контейнеров: **loader** (переопределяет `entrypoint`) и **dashboard** (использует CMD по умолчанию).

### 4.3 ETL-загрузчик (`app/loader.py`)

Логика работы:

1. Ожидание доступности PostgreSQL (retry-цикл на случай race condition).
2. Создание таблицы `marketing_campaigns` (`CREATE TABLE IF NOT EXISTS`).
3. Проверка: если данные уже загружены — пропуск (идемпотентность).
4. Чтение `/data/marketing_spend.csv` (bind mount) и `INSERT` в таблицу.
5. Завершение работы (контейнер останавливается).

### 4.4 Dashboard (`app/dashboard.py`)

Dash-приложение с тремя визуализациями для анализа эффективности маркетинговых трат:

1. **Столбчатая диаграмма** — средний ROI по каналам: показывает, какие маркетинговые каналы (Social Media, Google Ads, Email, TV и др.) приносят наибольшую отдачу от вложенных средств.
2. **Диаграмма рассеяния** — зависимость выручки от затрат: каждая точка представляет отдельную маркетинговую кампанию. Размер точки соответствует количеству кликов, цвет — каналу продвижения.
3. **Линейный график** — динамика ROI во времени: показывает изменение эффективности маркетинговых кампаний по неделям.

Выпадающие списки сверху позволяют выбрать конкретный канал или продукт.

Пароли хранятся только в `.env` и не попадают в `docker-compose.yml` и Docker-образ (`.dockerignore`).

## 6. Инструкция по запуску

```bash
# 1. Перейти в директорию проекта
cd lab_02/

# 2. Сгенерировать данные (однократно)
python3 generate_data.py

# 3. Запустить все сервисы
docker compose up -d --build

# 4. Проверить статус
docker compose ps

# 5. Открыть дашборд в браузере
#    http://localhost:8050

# 6. Посмотреть логи
docker compose logs -f

# 7. Остановить и удалить контейнеры (данные БД сохранятся в томе)
docker compose down

# 8. Полная очистка (включая том с данными)
docker compose down -v
```
